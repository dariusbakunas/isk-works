# Calculation Evidence Redesign

## Purpose

Calculation Evidence is the canonical explanation surface for a manufacturing
candidate. The worksheet remains the canonical operational surface. Evidence
explains how backend projections produced the worksheet and profitability
summary without duplicating every material row.

## Design Principles

### Layout

The modal follows a fixed hierarchy:

1. Profit accounting statement
2. Assumptions
3. Material cost derivation
4. Installation cost derivation
5. Duration derivation
6. Excluded costs
7. Exact formulas and provenance

It uses:

- a wide, viewport-constrained modal;
- one modal body scroll container;
- a fixed header and footer;
- compact tables with right-aligned tabular values;
- exact formulas collapsed by default;
- explicit incomplete states;
- responsive columns that stack on narrow viewports.

### Ownership

- Candidate previews remain the data source.
- `MoneyAmount` and money formatters remain responsible for ISK display.
- Facility profiles, installation breakdowns, blueprint assumptions, worksheet
  projections, and profitability basis remain backend-owned.
- Existing dialog, button, alert, and typography conventions remain in use.

React only renders a Rust-generated evidence projection. It never calculates
values itself.

Material requirements apply modifiers to each item and round required
quantities according to the Rust facility formula. Evidence therefore reports
backend-produced running quantities and cost totals rather than recreating
aggregate arithmetic in React.

Installation cost uses the EVE adjusted-price EIV basis supplied by ESI or an
explicit manual basis. System cost index, job-cost reduction, SCC surcharge,
facility tax, alliance surcharge, and fixed supplemental cost remain distinct
backend terms.

## Information Hierarchy

### Profit

Display as an accounting statement:

`Expected revenue - adjusted material cost - installation cost = estimated profit`

Profit and margin are unavailable when any required term is unavailable.
Revenue is not reduced by costs. Profit includes installation cost. The margin
is generated by Rust from estimated profit and expected revenue.

### Assumptions

Summarize:

- facility name, structure type, and solar system;
- blueprint name, kind, ME, TE, and run availability;
- price source and revision-friendly observation context;
- material and output pricing policies.

Opaque IDs remain in advanced provenance.

### Material Cost

Explain the backend sequence without repeating worksheet rows:

- base recipe requirements and runs;
- blueprint ME;
- structure material reduction;
- rig material reductions;
- final rounded requirements;
- resulting market material estimate.

Intermediate totals and multipliers originate from Rust.

### Installation Cost

Show the actual production terms:

- adjusted-price EIV basis;
- unmodified system-index cost;
- job-cost reduction;
- system-index cost;
- SCC surcharge;
- facility tax;
- alliance surcharge;
- fixed supplemental cost;
- total installation cost.

### Duration

Show backend-projected running duration:

- blueprint base duration for all runs;
- blueprint TE;
- structure time reduction;
- rig time reductions;
- final planned duration.

Character skill duration modifiers remain explicitly excluded.

### Excluded Costs

Render only backend-projected exclusions. Current supported profitability
exclusions include market fees, sales tax, hauling, incomplete installation
cost, and the distinction between market material estimate and projected
inventory cost. Blueprint-copy acquisition and character-skill duration are
shown only when the backend evidence projection explicitly marks them.

### Exact Formulas And Provenance

Collapsed by default. Contains:

- backend calculation traces;
- full-precision factors;
- formula versions;
- price-source revision and capture time;
- facility profile revision;
- recipe fingerprint and blueprint type ID.

## Component Structure

- `CalculationEvidenceModal`
- `CalculationEvidenceProfit`
- `CalculationEvidenceAssumptions`
- `CalculationEvidenceMaterialCost`
- `CalculationEvidenceInstallation`
- `CalculationEvidenceDuration`
- `CalculationEvidenceExcludedCosts`
- `CalculationEvidenceExactFormulas`

The modal components render a serialized Rust projection. They do not calculate
money, percentages, duration, material adjustments, pricing, or rounding.

## Backend Projection

The candidate preview response (`POST /api/build-plans/candidate-preview`)
exposes the calculation-evidence projection.

The projection contains display-ready exact values and structured terms. React
may format timestamps and durations for locale, but it does not derive formula
outputs.

## Accessibility

- `role="dialog"`, `aria-modal`, and a labelled heading;
- close button, backdrop close, and Escape close;
- initial focus moves into the modal and returns to the trigger;
- disclosure uses a native `details` element;
- tables retain textual operators and headings;
- incomplete terms use text in addition to color;
- one scroll container prevents competing keyboard scroll regions.

## Responsive Behavior

The modal is capped by viewport width and height. Assumption columns and
calculation tables stack or become horizontally scrollable at narrow widths.
Amounts remain right aligned with tabular numerals. Footer actions remain
reachable without nesting a second body scroll region.

## Browser Verification

Verify:

- Rifter candidate;
- capital-ship or other large recipe;
- missing output price;
- manual output price without a market observation;
- missing material prices;
- modal with exact formulas collapsed and expanded;
- keyboard open, disclosure, close, and focus return;
- desktop and mobile viewport overflow.

## Future Extensibility

Additional modeled costs should first become Rust profitability terms and
evidence projection fields. The modal can then render new terms without
changing calculation ownership. Evidence export should serialize the backend
projection rather than scrape rendered text.
